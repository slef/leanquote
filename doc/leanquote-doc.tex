\begin{abstract}
\noindent
\textsf{leanquote} typesets declarations of a Lean~4 file in a \LaTeX{} document by name:
\cs{leanquotesetup}\verb|{file=Abstract.lean}| followed by \cs{leanquote}\verb|{main_theorem}| prints the
declaration \texttt{main\_theorem} exactly as it appears in the Lean source, read at compile time.
The prose stays in \LaTeX, and the code is never retyped or pasted.
A misspelled name is an error. When local build artifacts are available, the package warns
if the Lean source is newer than its compiled file.
It needs nothing on the Lean side beyond the usual \texttt{lake build}; an optional exporter lets
Lean itself report the exact extent of each declaration.
It works with pdf\LaTeX, Lua\LaTeX, and Xe\LaTeX.
\end{abstract}

\section{Why}

Papers that use a formalization often reproduce its definitions and main theorem statements,
so that a reader can check that the formal statements say what the paper claims.
Pasting code by hand invites the copy in the paper to drift from the code that Lean checked.
With \textsf{leanquote} the paper names the declarations it wants, and \LaTeX{} copies them from
the Lean file each time the paper is compiled.
The package was written for papers that present a short, human-readable
\texttt{Abstract.lean}, containing the definitions and main statements of a formalization and
proved through a bridge to the full development. Other Lean~4 files can be quoted too;
unusual layouts need the optional exporter (Section~\ref{sec:export}).

\section{Usage}

Put \texttt{latex/leanquote.sty} where \LaTeX{} can find it, for example beside your
paper's \texttt{.tex} file or in \texttt{TEXINPUTS}, then load it as follows.
No shell escape is needed, and \LaTeX{} does not run Lean.

\begin{latexsrc}
\usepackage{leanquote}
\leanquotesetup{project=../lean/}            % root of the Lake project (optional)

\leanquotesetup{file=TranslationTiling/Abstract.lean} % default file
A prototile is a finite list of points of $\mathbb{Z}^3$:
\leanquote{Point, Prototile}
\end{latexsrc}

\leanquotesetup{file=TranslationTiling/Abstract.lean}
\noindent\begin{minipage}{\linewidth}
\noindent produces (with the file shipped in the package's \texttt{example} directory):

A prototile is a finite list of points of $\mathbb{Z}^3$:
\leanquote{Point, Prototile}
\end{minipage}

\medskip
\begin{description}
\item[\cs{leanquotesetup}\texttt{\{\meta{options}\}}]
  sets defaults for the rest of the document (or the current group), including
  \opt{file=}\meta{path}. The path is relative to \opt{project}, if set.
  It can be used in the preamble.
\item[\cs{leanquote}\texttt{[\meta{options}]\{\meta{names}\}}]
  typesets the comma-separated declarations \meta{names} of the current file, together, in one
  listing. The \opt{file=}\meta{path} option selects a file for this call without changing
  the default; it works without a preceding setup. A file must be supplied
  by one of these methods. With \opt{imports}, the file's import block is prepended
  once in the same listing, before the declarations. An empty name list,
  \verb|\leanquote[imports]{}|, quotes only the imports.
\end{description}

\begin{latexsrc}
\leanquote[doc,file=Other.lean]{Connected}
\leanquote[imports,file=Other.lean]{Point, Connected}
\leanquote[imports,file=Other.lean]{}
\end{latexsrc}

With \opt{project=../lean/}, \texttt{.lean} paths are relative to that directory;
include the trailing slash. Without \opt{project}, paths are relative to the
\LaTeX{} working directory. Explicit \texttt{.leanquote} paths and the \opt{olean},
\opt{source}, and \opt{logo} options are used as supplied, without a \opt{project} prefix.

The import block contains the \texttt{module} and \texttt{[public|private|meta] import}
lines at the top of the file. Comments are omitted, including comments spanning several
lines. For instance, \verb|\leanquote[imports]{}| gives:

\leanquote[imports]{}

\noindent The Boolean option is initially false; bare \opt{imports} means
\opt{imports=true}. It can be set in \cs{leanquotesetup}, with a per-call
\opt{imports=false} to omit imports for one quote. Normal declaration names such as
\texttt{import} and \texttt{imports} remain available.

\noindent Names may be short (\texttt{Tiles}) or qualified
(\texttt{TranslationTiling.Abstract.Tiles}). A qualified name matches a declaration inside the
corresponding \texttt{namespace}: the requested name must be the full name or a dotted suffix
of it. Namespace and section scope are tracked, including escaped name components such as
\texttt{«A B».foo}. An unknown name is an error; an ambiguous short name is a warning,
and the first match is used.

With \opt{proof=false}, theorems and lemmas are shown without their proofs, which the reader
does not need in order to check the statement; definitions keep their bodies:

\begin{latexsrc}
\leanquote[proof=false]{tiling_coRE_complete}
\end{latexsrc}
\leanquote[proof=false]{tiling_coRE_complete}

\noindent Proof hiding preserves local \texttt{let}/\texttt{have} bindings,
\texttt{match} expressions, and \texttt{do} blocks in the statement.
Brackets, literals, comments, escaped names, and default parameter values such as
\texttt{(k :} $\mathbb{N}$ \texttt{:= 3)} do not act as proof delimiters.
A \texttt{where} proof is omitted as a whole.
Set \opt{proof=false} once in \cs{leanquotesetup} to hide all proofs.

With the \opt{doc} option, the doc comment is included:

\begin{latexsrc}
\leanquote[doc]{Tiles}
\end{latexsrc}
\leanquote[doc]{Tiles}

Quotes work in figure bodies, ordinary macro arguments, and footnotes, with no guarantee
for moving arguments such as caption or heading text.

\section{Lean listing format}

\paragraph{Code font.} \opt{basicstyle} is a \textsf{listings} option forwarded by
\textsf{leanquote}. The default \texttt{leanquote} style uses \verb|\ttfamily\small|.
Include both the font family and size when overriding it:
\begin{latexsrc}
\leanquotesetup{basicstyle=\ttfamily\footnotesize}
\leanquote[basicstyle=\ttfamily\small]{Tiles}
\end{latexsrc}
For an explicit point size, use \verb|\ttfamily\fontsize{9.5}{11.5}\selectfont|;
the arguments specify font size and baseline spacing. This manual uses that setting
to fit its long example lines.

\paragraph{Box colors.} With \opt{box=true} (the default), set the background with
\opt{boxback} and the border with \opt{boxframe}
(without affecting other tcolorboxes).
Both accept \textsf{xcolor} names and expressions such as \opt{blue!3}:
\begin{latexsrc}
\leanquotesetup{boxback=blue!3,boxframe=blue!50}
\leanquote[boxback=green!3,boxframe=green!50]{Tiles}
\end{latexsrc}
\leanquote[boxback=green!3,boxframe=green!50]{Tiles}
\noindent The frame color also applies to the logo outline. Verification badges
retain their red background.

\paragraph{The logo.} With \opt{logo=}\meta{file}, the image appears in the top-right corner of
each box, followed by \cs{leanquotelogomark}, a small ``TM'' in the blue of the Lean logo.
The Lean trademark policy (\url{https://lean-lang.org/trademark-policy}) asks that the Lean logo
always be accompanied by a trademark symbol; for other logos, redefine
\cs{leanquotelogomark} as empty with
\verb|\renewcommand{\leanquotelogomark}{}|. The Lean logo is not included in the package.
\cs{leanquotetrademark} prints the notice ``\leanquotetrademark'' Give it once in the paper,
for example in the acknowledgments.

\paragraph{Syntax highlighting.} The \texttt{leanquote} style colors four classes of words: keywords and commands
(\texttt{def}, \texttt{theorem}, \texttt{fun}, \texttt{by}, \dots) in blue; sorts and the
common types and type classes of core Lean and Mathlib (\texttt{Prop}, \texttt{Nat},
\texttt{Fin}, \texttt{Set}, \texttt{Finset}, \texttt{List}, \texttt{Real},
\texttt{Polynomial}, \dots) in green; common tactics (\texttt{simp}, \texttt{exact},
\texttt{omega}, \dots) in purple; and \texttt{sorry} in red. A word directly after a dot is
part of a qualified name and is not colored: in \texttt{Set.univ} the head \texttt{Set} is green,
but import paths such as \texttt{Mathlib.MeasureTheory.Measure.Lebesgue.Basic} and fields such as
\texttt{x.Measure} stay plain (listings key \opt{leanquotenodot}, on in this style).
String and character literals are brown. Raw strings, interpolation expressions, nested
comments, and escaped identifiers are recognized separately, so their contents do not
accidentally become keywords or comments. The colors are
\texttt{leanquotekeyword}, \texttt{leanquotetype}, \texttt{leanquotetactic}, and
\texttt{leanquotestring}, and can be
redefined with \cs{definecolor}. Words are added to a class with the \textsf{listings} keys
\opt{morekeywords}, \opt{morekeywords=[2]} and \opt{morekeywords=[3]}, for example the
document's own types:
\begin{latexsrc}
\leanquotesetup{morekeywords=[2]{Prototile, Point}}
\end{latexsrc}
The forwarded \textsf{listings} option \opt{stringstyle} overrides the string and character
style for one quote or through \cs{leanquotesetup}:
\begin{latexsrc}
\leanquotesetup{stringstyle=\color{brown}}
\leanquote[stringstyle={}]{Tiles} % plain strings and characters
\end{latexsrc}
Set \opt{showstringspaces=true} to mark spaces inside string and character literals.
Starred \opt{literate} replacements leave strings and comments unchanged:
\begin{latexsrc}
\leanquote[literate=*{->}{{$\to$}}1]{Tiles}
\end{latexsrc}
With \opt{texcl=true}, text after a Lean \texttt{--} line-comment opener is interpreted as
\LaTeX; \texttt{--} inside a string or block comment stays literal.

\paragraph{Unicode and engines.} The \texttt{leanquote} listings style typesets about a hundred of Lean's Unicode symbols
($\mathbb{N}\ \mathbb{Z}\ \mathbb{R}\ \to\ \forall\ \exists\ \sum\ \bigcup\ \le$ \dots, Greek letters, sub- and superscripts) as math, under
pdf\LaTeX{} through listings' \opt{literate} mechanism, and under Lua\LaTeX{} and Xe\LaTeX{} by
making these characters active inside listings. Other symbols can be added with \opt{literate}
in a style of your own (pdf\LaTeX), or by choosing a monospace font that contains them
(Lua\LaTeX, Xe\LaTeX).

The listings language is called \texttt{leanquote-lean}, so that a document's own
\verb|\lstdefinelanguage{Lean4}| does not interfere with it.

\section{How declarations are found}

The package reads the Lean file with \LaTeX's own file input and uses the standard layout of
Lean code. A declaration starts at a line in column~0 of the form
\begin{center}
\texttt{[@[\meta{attributes}]] [\meta{modifiers}] \meta{keyword} \meta{name} \dots}
\end{center}
where \meta{keyword} is one of \texttt{def}, \texttt{theorem}, \texttt{lemma}, \texttt{abbrev},
\texttt{structure}, \texttt{inductive}, \texttt{instance}, \texttt{class}, \texttt{axiom},
\texttt{opaque}, and the modifiers are \texttt{public}, \texttt{private}, \texttt{protected},
\texttt{noncomputable}, \texttt{partial}, \texttt{unsafe}, \texttt{nonrec}, \texttt{meta}.
Attribute lines just above it are included, and so is the doc comment if \opt{doc} is set.
Nested comments and literals are skipped when recognizing declarations. Bracketed terms,
including syntax quotations, stay within their enclosing declaration.
Comments are omitted from the import block, including inline and multiline comments.
The header may include \texttt{module} or \texttt{prelude}, and import commands may span lines.
The declaration continues while lines are blank, indented, or start with \texttt{|},
\texttt{termination\_by}, \texttt{decreasing\_by} or \texttt{deriving}; trailing blank lines are
dropped. This matches the layout used by Mathlib and by most Lean code, including
\texttt{match} alternatives and \texttt{inductive} constructors.

Without an export, the scanner recognizes this layout, not arbitrary Lean syntax extensions.
Unlisted continuation lines in column~0 are cut short. Use an export for unusual layouts
or declarations introduced by macros.

The package writes one temporary file
\meta{jobname}\texttt{-leanquote-}\meta{n}\texttt{.lean} per listing.
These files are not deleted automatically. You might add \verb|*-leanquote-*.lean|
to \texttt{.gitignore}.

\section{What has Lean checked?}\label{sec:compiled}

\LaTeX{} does not run Lean, but it can read what Lake leaves behind. \textsf{leanquote} marks a
quote, in the corner of its box, when it is not known to be fully checked, since a warning in the
log is easily missed. Without a box, the mark appears in red above the code.

\begin{center}
\begin{tabular}{@{}lp{0.62\linewidth}@{}}
\toprule
Mark & Meaning \\
\midrule
\textsc{unverified} & the \texttt{.lean} file is newer than its compiled \texttt{.olean} (edited
  since the last build), or its last \texttt{lake build} failed (Lake deletes the \texttt{.olean}
  but keeps its \texttt{.trace}); an export's source or build has changed, or it lacks
  verification metadata; with \opt{verify=true}, also when there is no compiled file \\
\textsc{uses sorry} & the declaration depends on \texttt{sorry}, anywhere in its dependencies
  (needs an export, Section~\ref{sec:export}) \\
\textsc{sorry in file} & Lake's build log for the file reports a \texttt{sorry} (without an
  export) \\
\textsc{extra axioms} & the declaration depends on axioms beyond \texttt{propext},
  \texttt{Classical.choice} and \texttt{Quot.sound}, for instance through \texttt{native\_decide}
  (needs an export) \\
\bottomrule
\end{tabular}
\end{center}

\noindent The compiled files are looked for under \opt{project}
(\texttt{.lake/build/lib/lean/\dots}), or at the actual artifact path recorded in a v2 export.
When a compiled file is present, its timestamp is compared with the source. An export's
axiom list is checked against the dependency fingerprint of its Lake build: if an imported
proof changes and the module is rebuilt, re-export before relying on its axiom information.

The \opt{verify} option chooses how strict to be:
\begin{center}
\begin{tabular}{@{}llll@{}}
\toprule
& compiled, up to date & stale or failed build & no compiled file \\
\midrule
\opt{verify=auto} (default) & checks as above & \textsc{unverified} & note in the log \\
\opt{verify=true} (or \opt{verify}) & checks as above & \textsc{unverified} & \textsc{unverified} \\
\opt{verify=false} & nothing & nothing & nothing \\
\bottomrule
\end{tabular}
\end{center}
The default catches the common mistakes of editing the Lean file or breaking its build and then
recompiling the paper. With no compiled file, it writes a note to the log
(Section~\ref{sec:publishing}). With \opt{verify=true}, those quotes are marked too:

\leanquote[verify=true]{Adjacent}

\noindent (The example file shipped with the package has no compiled \texttt{.olean}.)
The log explains each mark, for example:
\begin{latexsrc}
Package leanquote Warning: ../lean/TranslationTiling/Abstract.lean is newer
(leanquote)  than its compiled file ... The code shown may not be what Lean
(leanquote)  checked (the quote is marked UNVERIFIED): run lake build.
\end{latexsrc}

\paragraph{What is not detected.} Without an export, a \texttt{sorry} in another file that the
quoted declaration depends on (say, in the bridge to the full development) is not seen, because
Lake reports a \texttt{sorry} only in the file that contains it; the export's axiom list covers
all dependencies. And if an imported file is broken while the quoted file is unchanged, the quoted
file keeps its last successful \texttt{.olean}, so its quotes still show code that Lean checked,
against the previous version of its imports.
The compiled check relies on file modification dates; copying a project without
preserving them can cause false warnings or hide stale code.

The old option name \opt{check} is also accepted. The marks' appearance can be changed by
redefining \cs{leanquotebadge}\verb|{label}| (in the box) and \cs{leanquotebadgetext}\verb|{label}|
(without a box).

\section{Optional: exact boundaries and axioms from Lean}\label{sec:export}

For files laid out unusually, Lean itself can report where each declaration starts and ends.
From the root of the Lake project, run the exporter shipped with the package:
\begin{latexsrc}
path/to/leanquote/leanquote-export TranslationTiling.Abstract [More.Modules ...]
\end{latexsrc}
It builds each module and writes
\path{.lake/build/leanquote/TranslationTiling/Abstract.leanquote}, inside the build directory.
From then on, \cs{leanquote} finds this export automatically and uses Lean's declaration ranges;
nothing changes in the document. The export also lists, for each declaration, the axioms it
depends on (as \texttt{\#print axioms} reports them), which gives the \textsc{uses sorry} and
\textsc{extra axioms} marks. The export also records the source as compiled. If the
\texttt{.lean} file is edited afterwards, the package warns and falls back to reading the
\texttt{.lean} file directly, so quotes of a \texttt{.lean} file show its current code.
The exporter runs through \texttt{lake env lean --run}; nothing is added to the Lean project.
It requires modules configured in a Lake \texttt{lean\_lib}, with source and build paths
inside the project. The output directory mirrors each module's actual source path.

An export placed next to the \texttt{.lean} file is also found, and an export can be quoted
explicitly with \verb|\leanquote[file=Abstract.leanquote]{...}|.
An explicitly selected export deliberately shows its recorded snapshot. With verification
enabled, changed source or a different local build produces a warning and an
\textsc{unverified} mark. When no local build
is available, \opt{verify=auto} uses a v2 snapshot's recorded axioms; \opt{verify=true} marks
it unverified.

For an explicit export, \opt{root=../lean/} prefixes the source path recorded in the
export; \opt{source=../lean/Other.lean} overrides it with a complete path.
Recorded compiled artifact paths are relative to \opt{project}, or to \opt{root} if
\opt{project} is unset. These options locate files for verification; they do not
change the snapshot shown.

The exporter resolves source and compiled paths through Lake, including custom source/build
directories. Version~2 records the build fingerprint and prefixes every code line, so literal
format markers inside Lean strings cannot truncate a quote. Version~1 exports remain readable
but are marked \textsc{unverified}; re-run the exporter to upgrade them.
The v2 format rejects control characters in metadata (including names and paths),
whitespace inside axiom names, and bare carriage returns in source. LF and CRLF are supported.

\section{Publishing: arXiv, CI, Overleaf}\label{sec:publishing}

ArXiv.org compiles the \LaTeX{} source itself, and so do continuous-integration builds and online
editors such as Overleaf, usually without a Lean build. There, the \texttt{.lean} files are
read as usual (include them, and \texttt{leanquote.sty}, in the upload). Without compiled
files or exports, the default \opt{verify=auto} does not mark quotes \textsc{unverified}:
those builds cannot check the local Lean build. Portable exports can still report
\textsc{uses sorry} or \textsc{extra axioms} from their recorded axiom lists.
Check where Lean is built:
\begin{enumerate}
\item run \texttt{lake build}, then compile the paper locally, and make sure no quote is
  marked \textsc{unverified} and the log has no \textsf{leanquote} warning;
\item then upload, or push to the CI or online editor.
\end{enumerate}
If a CI pipeline does build Lean before the paper, set \opt{verify=true} there, so that a
missing compiled file is noticed as well.

\section{Texlish}

\href{https://texlish.org}{Texlish} passes \LaTeX{} commands through, and its one-argument
syntax reads naturally:
\begin{latexsrc}
::use leanquote
\leanquotesetup: file=Abstract.lean
\leanquote: main_theorem
\end{latexsrc}
With an optional argument, use braces: \verb|\leanquote[doc]{main_theorem}|.
For imports only, use \verb|\leanquote[imports]{}|.

\section{Related tools}

Several tools include code from source files in documents; as far as we know, none quotes Lean
declarations by name in an ordinary \LaTeX{} document or checks the quoted code against the
compiled module.
\begin{itemize}
\item \textbf{Marker-based inclusion in \LaTeX.}
  \textsf{catchfilebetweentags} (\verb|\ExecuteMetaData|), \textsf{listings} line ranges with
  marker comments, \textsf{piton} ranges, and \textsf{tagsnip} include the code between markers
  that the author adds to the source; \textsf{minted}'s \texttt{rangeregex} selects code by a
  regular expression, and Pygments has a Lean~4 lexer. These work for any language but need
  markers or patterns, and do not know Lean's declarations.
\item \textbf{Lean-native documents.} Verso and SubVerso, by the Lean FRO, include anchored
  regions of Lean modules in documents written in Verso, with Lean's own highlighting, and fail
  when a code block no longer matches its module; Verso's manual genre also produces \TeX.
  They are the natural choice for documents written in Lean; \textsf{leanquote} is for
  papers written in \LaTeX.
\item \textbf{Blueprints.} \textsf{leanblueprint}'s \verb|\lean{...}| links informal statements to
  Lean declarations by name, and \texttt{checkdecls} checks that the names exist;
  LeanArchitect generates blueprint text from annotated Lean declarations
  (\verb|\inputleannode{...}|). Both connect \LaTeX{} and Lean by name, without quoting code,
  and can be used together with \textsf{leanquote}.
\item \textbf{Other proof assistants.} Isabelle's document preparation and the
  \textsf{cartouches} tool (formerly \textsf{isasnips}), which names snippets after declarations;
  Agda's \LaTeX{} backend combined with \textsf{catchfilebetweentags}; and Alectryon for Rocq.
  There the checker itself generates the document, which keeps code and proofs in sync.
\item \textbf{Lean listings style.} Lean's documentation provides \texttt{lstlean.tex}, a
  \textsf{listings} definition of Lean with a Unicode table, which inspired ours.
\end{itemize}
The idea of including Lean snippets in papers to keep them in sync with the code was raised on
the Lean Zulip by Eric Wieser in 2022
(thread ``\href{https://leanprover-community.github.io/archive/stream/113488-general/topic/MathemaTeX.html}{MathemaTeX}'').
